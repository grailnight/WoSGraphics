# Облака в пониженном разрешении с временным накоплением

Идея взята у Proper Shaders (порт Cloudworks), код наш и маршит наш слой.

## Что изменилось

Раньше bloom-шейдер маршил слой облаков для **каждого пикселя экрана каждый кадр**: 64 шага, а на плотных шагах ещё по 4 выборки к солнцу. Теперь работа делится так:

1. **`cloud_march.cso`.** Работает на bloom-драве. Маршит буфер в 1/2 или 1/4 разрешения экрана, причём только один пиксель из каждого блока 2×2 за кадр. Слот блока меняется каждый кадр, сдвиг первой выборки тоже.
2. **`cloud_resolve.cso`.** Собирает полный буфер из свежих выборок и прошлого кадра. Прошлый кадр репроецируется по середине промаршированного отрезка луча и удерживается в диапазоне соседних свежих выборок.
3. **bloom (`bloom_gta.hlsl` → exWoS `0x072A8139.bloom.pcps`).** Если DLL привязала буфер (s4, маркер 11 в c36.w), bloom берёт облака из него. Если нет, маршит по пикселю, как раньше.

Буфер не зависит от геометрии: каждый луч проходит весь слой, как будто его пиксель — небо. Поэтому при апсемпле нет швов по силуэтам, а при репроекции нет дыр от раскрытия. Обрезку зданиями bloom считает в полном разрешении:

- **Поверхность перед слоем:** облаков нет.
- **Поверхность за промаршированным отрезком:** значение из буфера.
- **Поверхность внутри слоя:** короткий попиксельный марш до неё (24 шага).

Масштабировать буфер в предположении равномерной плотности пробовали. Это ломалось у основания слоя: ошибка по T на башнях доходила до 0.58.

## Замер (`test/gpu_test.exe`, RTX 3060, 1920×1080)

| | GPU, мс |
|---|---|
| Старый попиксельный марш | 22.3 |
| 1/2 + накопление (march + resolve + composite) | 2.3–3.8 |
| 1/4 + накопление | 0.9–2.4 |
| Камера внутри слоя: старый / 1/2 | 30.4 / 4.2 |

Нижняя граница — сцена, где почти нет геометрии внутри слоя. Верхняя — тестовая сцена, где башни внутри слоя занимают 21% экрана.

Качество сравнивалось с эталоном (тот же марш на 240 шагов). Для неба средняя |ΔT| — 0.0011 (старый путь даёт 0.0009), на быстром повороте — 0.0018. Для геометрии внутри слоя — 0.0009 (старый путь даёт 0.0004). Картинки лежат в `test/*.png`, в порядке: старый, новый, эталон, |разница|×8.

**В игре ещё не проверено.**

## Настройки

F3 → «Облака» → «Разрешение облаков». Секция `[CloudLowRes]` в `WoS_VolumetricClouds\clouds_menu.ini`:

- **`Divisor`:** 1 — по пикселю (как раньше), 2 — половина (по умолчанию), 4 — четверть.
- **`MarchedBlend`** (0.5): сколько истории сохраняет пиксель, промаршированный в этом кадре.
- **`SpatialMix`** (0.15): насколько ожидающий пиксель тянется к свежей интерполяции.
- **`ClampExpand`** (0.5): допуск истории. Если меньше, видны блоки 2×2; если больше, появляются шлейфы.

Состояние раз в секунду пишется в `cloud_lowres_status.json`.

## Сборка

- `build_shaders.ps1` — собирает march и resolve.
- `..\..\WoS_VolumetricClouds\native\build_gta_lighting.ps1` — собирает bloom. Bloom и march делят `wos_clouds.hlsli`, поэтому после правки пересобирать оба.
- DLL собирается через `..\full_deferred_staged\build_integration.ps1`.
- Тест: `test\build_test.cmd`, затем `test\gpu_test.exe` и `python test\make_png.py`.

- `winmm.pre_cloud_lowres_20261001.dll` → `winmm.dll`
- `0x072A8139.bloom.pcps.pre_cloud_lowres_20261001` → `exWoS\GtaStyleLighting\GAME\0x072A8139.bloom.pcps`
- `wos_clouds.hlsli.pre_cloud_lowres_20261001`, `bloom_gta.hlsl.pre_cloud_lowres_20261001`, `wos_clouds_menu.cpp.pre_cloud_lowres_20261001` — исходники.
